# Spec — `[[nodes]]` 行尾注释强制规则

> 状态:已与郑旭对齐,等用户复核后转 writing-plans
> 日期:2026-09-23
> 范围:纯文档变更,不动 `graph_query.py`

## 1. 背景与动机

`AX-GRAPH` 的 `[[nodes]]` 块散落在 L1/L2/L3/longlife 多个 TOML 文件里。
查询工具(`graph_query.py`)以节点 `id` 和 `desc` 字段作为"人类可读"的主要信息源;
但人在**直接翻看 TOML 源文件**(例如做 PR diff、grep 漂移、人工加节点)时,
只能看到 `id = "..."` 这种字符串,而 `desc` 字段在 5–15 行之后,扫读困难。

`SCHEMA.md §6` 的完整示例已经在 `[[nodes]]` 行尾示范了注释格式
(L134:`[[nodes]]  # 节点 func.agent.foo.bar: 职责一句话`),
说明作者早就想用行尾注释做"屏快照"。本次把它**从示范升格为全员规则**。

## 2. 设计目标

- 在不改 `graph_query.py` 的前提下,让人翻看 TOML 源文件时**一眼读懂每个节点的角色**。
- 注释内容与 `desc` 保持一致,避免产生新的事实源。
- 新规则**只约束新加节点**,对现存 119 个节点不追溯。
- 把规则挂在 AGENTS.md §5(铁律),而不是 §6(流程),因为它是"加节点时必须有 X"。

## 3. 规则定义(铁律 6 全文)

> **6. `[[nodes]]` 块的尾注释**。每条 `[[nodes]]` 块内第一字段(默认是 `id = "..."`)
> 所在那一行的行尾,必须紧跟 `# 节点 <id>: <≤15 字说明>`(目标 ≤15 字,上限 20 字;
> 超过 20 字 PR 评审可拒),说明须与该节点的 `desc` 保持一致(子串即可,不必逐字相同)。
> **适用范围**:所有存在 `[[nodes]]` 数组的 TOML 文件(L1/L2/L3/longlife)。
> **生效起点**:本规则落地之后新增的 `[[nodes]]` 必须遵守;落地前已存在的节点不补、不追溯。
> **违规处理**:目前靠人/PR 评审;后续若验证有需要,新增独立 check 脚本或为
> `--validate` 加 `--require-comment` 开关——届时单独立项,本规则不在此范围改动工具。

### 3.1 格式约束解析

| 维度 | 取值 | 拍板来源 |
|---|---|---|
| 注释起始符 | `#` | TOML 语法 |
| 注释形态 | 行尾(trailing)注释 | 复用 SCHEMA.md §6 L134 示范样式 |
| 必含字段 | 节点 id + 说明短语 | 用户确认(id + ≤15 字说明) |
| 字限 | 目标 ≤15,上限 20 | 用户确认(上限 20 是 PR 评审软约束) |
| 与 desc 一致性 | 子串即合规,不必逐字 | 用户确认(desc 是事实源,注释是其屏快照) |

## 5. 错误处理

本规则**没有运行时错误**(纯文档变更),但有 3 类"写错了需要回头"的场景:

| 场景 | 检测方法 | 处理 |
|---|---|---|
| §5 铁律 6 条文写得太严 / 太松,以致人无法遵守 | 实操中加新 `[[nodes]]` 时反复读条 | 由 PR 评论提出,改条文字面或字限(改 AGENTS.md 仍属人决) |
| SCHEMA.md §1 表格对不齐 | 视觉检查 / markdown linter | 编辑行内 `\|` 对齐空格 |
| §6 blockquote 文字与新条文字面打架 | 比对引用路径是否一致 | 同步改字 |
